# Architecture

A small React + TypeScript + Vite SPA that renders the **same product page twice** — once
intentionally poor (`/bad`), once optimized (`/optimized`). There is no in-app metrics widget;
Core Web Vitals are measured with **Lighthouse via Chrome DevTools** (Mobile preset).

## Folder map

```
frontend-core-web-vitals-lab/
  public/images/              generated by scripts/generate-assets.ts (not checked in as binaries)
  scripts/generate-assets.ts  idempotent sharp-based image generator (postinstall)
  src/
    app/
      App.tsx                 layout shell: Header, <Outlet/>, Footer
      routes.tsx              <BrowserRouter> + <Routes> for /, /bad, /optimized, /notes
    components/
      Header.tsx, Footer.tsx  chrome + nav
      ProductCard.tsx         related-product card (stable flag controls image dims)
      Reviews.tsx             review list (stable flag controls avatar dims)
    lib/
      expensiveWork.ts        runExpensiveSync() + worker protocol types
      cartWorker.ts           Web Worker performing the same work off the main thread
    pages/
      HomePage.tsx            intro + links
      BadPage.tsx             intentionally poor page (LCP/CLS/INP problems)
      OptimizedPage.tsx       the fixes
      NotesPage.tsx           explainer + how to measure + pros/cons/pitfalls
    styles/                   global.css (tokens/reset/base) + layout.css (components)
    main.tsx                  createRoot
  .github/workflows/ci.yml    typecheck · lint · test · build
```

## Bad vs optimized, by metric

- **LCP** — `/bad`: a 1.5 MB unoptimized JPEG, lazy-loaded, no `width`/`height`, render
  delayed ~1s. Under Mobile throttling this becomes a slow LCP. `/optimized`: sized WebP with
  `loading="eager"` + `fetchPriority="high"` and reserved dimensions.
- **CLS** — `/bad`: a promo banner and a notice bar are injected ABOVE already-rendered
  content, the title typography changes after load, and every image/avatar is unsized.
  `/optimized`: the banner slot is reserved up front, images/avatars are sized, typography is
  stable.
- **INP** — `/bad`: synchronous ~700ms busy-loop in the click handler.
  `/optimized`: the same work runs in `cartWorker.ts` (Web Worker); the handler returns
  immediately and the UI never blocks.

## Measuring

Open `/bad` or `/optimized`, then run **Chrome DevTools → Lighthouse** with the **Mobile**
preset. Mobile throttling (Slow 4G + slowed CPU) is what makes the difference visible: the
1.5 MB hero on `/bad` is slow to fetch and shifts the layout when it finally paints, while the
~15 KB WebP on `/optimized` is fast and stable. For INP, record a “Add to cart” click in the
**Performance** panel and compare the main-thread blocking.

> Why Mobile and not Desktop? On localhost with no throttling, even a 1.5 MB image loads in a
> few milliseconds, so the `/bad` route’s LCP/CLS problems don’t show up — which would defeat
> the demo.

## Images

There are no binary assets in the repo. `scripts/generate-assets.ts` (run on `postinstall` and
via `pnpm assets`) uses `sharp` to produce:

- `hero-large.jpg` — deliberately large, unoptimized JPEG (quality 100, no mozjpeg, 4:4:4) for
  `/bad`.
- `hero-optimized.webp` — the same scene as an optimized WebP for `/optimized`.
- `product-1.webp`, `product-2.webp` — sized thumbnails.

The script is idempotent: it no-ops when all four files already exist.
